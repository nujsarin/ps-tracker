# Project Sales Tracker · ช่วงทดลอง (Pilot แบบ A)

แอปบันทึกและติดตามโครงการสำหรับทีม Project Sales เป็นไฟล์ HTML ไฟล์เดียว ข้อมูลทั้งหมดเก็บและเข้ารหัสในมือถือของพนักงานแต่ละคน ไม่มี server

## ไฟล์ในชุดนี้ (อัปโหลดขึ้น GitHub ทั้ง 7 ไฟล์)

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวแอปทั้งหมด |
| `sw.js` | ทำให้แอปเปิดได้แม้ไม่มีเน็ต และอัปเดตเวอร์ชัน |
| `manifest.webmanifest` | ทำให้ติดตั้งลงหน้าจอหลักได้ |
| `icon.svg`, `icon-192.png`, `icon-512.png` | ไอคอนแอป |
| `README.md` | คู่มือนี้ |

## ขั้นตอนขึ้น GitHub Pages

1. เข้า github.com แล้วล็อกอินด้วยบัญชีของบริษัท (ควรใช้ Organization ของบริษัท ไม่ใช้บัญชีส่วนตัว)
2. กด **New repository** ตั้งชื่อ เช่น `ps-tracker` เลือก **Public** แล้วกด **Create repository**
3. ในหน้า repository กด **uploading an existing file** แล้วลากไฟล์ทั้ง 7 ไฟล์ลงไป (วางไว้ชั้นแรก ไม่ต้องใส่โฟลเดอร์) แล้วกด **Commit changes**
4. ไปที่ **Settings → Pages** ช่อง Source เลือก **Deploy from a branch** เลือก branch **main** โฟลเดอร์ **/ (root)** แล้วกด **Save**
5. รอ 1–3 นาที หน้าเดิมจะแสดงลิงก์ `https://[ชื่อบัญชี].github.io/ps-tracker/`
6. เปิดลิงก์ทดสอบเองก่อน แล้วจึงส่งลิงก์ให้กลุ่มทดลองทาง Teams

> ห้ามเปลี่ยนชื่อ repository หรือย้ายบัญชีหลังเริ่มใช้งาน ข้อมูลในมือถือผูกกับลิงก์นี้ ถ้าลิงก์เปลี่ยน แอปจะไม่เห็นข้อมูลเดิม

## อุปกรณ์ที่รองรับ

- iPhone / iPad: iOS / iPadOS 15 ขึ้นไป ใช้ Safari แล้ว **เพิ่มไปยังหน้าจอโฮม**
- Android: Android 9 ขึ้นไป ใช้ Chrome 100 ขึ้นไป แล้ว **ติดตั้งแอป**
- คอมพิวเตอร์: Chrome หรือ Edge รุ่นล่าสุด
- ไม่รองรับ: เปิดลิงก์ผ่าน LINE, Facebook หรือโหมดไม่ระบุตัวตน (แอปแสดงคำเตือนและปุ่มเปิดในเบราว์เซอร์)
- iPhone/iPad ที่ไม่ได้ติดตั้งลงหน้าจอโฮม Safari อาจลบข้อมูลเองถ้าไม่เปิดแอปเกิน 7 วัน
- เวอร์ชันขั้นต่ำข้างต้นประเมินจากความสามารถของเบราว์เซอร์ที่แอปใช้ ทดสอบอัตโนมัติบน Chromium แล้ว ควรทดสอบกับเครื่องจริงรุ่นเก่าสุดของสาขาก่อนใช้งานจริง

## ขั้นตอนสำหรับพนักงาน (ครั้งแรก)

1. เปิดลิงก์ด้วย **Safari (iPhone)** หรือ **Chrome (Android)**
2. ติดตั้งลงหน้าจอหลัก
   - iPhone: กดปุ่มแชร์ แล้วเลือก **เพิ่มไปยังหน้าจอโฮม**
   - Android: กดเมนู ⋮ แล้วเลือก **ติดตั้งแอป**
3. เปิดแอปจากไอคอนบนหน้าจอหลัก กรอก Emp ID ชื่อ สาขา ทีม และตั้ง PIN 6 หลัก แล้วเริ่มใช้งานได้ทันที

> หน้าวันนี้มีเช็กลิสต์เริ่มต้นใช้งาน 5 ขั้น ติ๊กถูกให้เองเมื่อทำจริง และมีหน้า **คู่มือใช้งาน** (ตั้งค่า → คู่มือใช้งาน)

## เครื่องที่ใช้ร่วมกัน (เช่น iPad สาขา)

- เพิ่มผู้ใช้ได้หลายคนในเครื่องเดียว: หน้าปลดล็อก → **เปลี่ยนผู้ใช้ / เพิ่มผู้ใช้** หรือ ตั้งค่า → **เปลี่ยนผู้ใช้**
- แต่ละคนมี PIN และฐานข้อมูลแยกกัน มองไม่เห็นข้อมูลของคนอื่น สำรองข้อมูลแยกคน
- Emp ID ซ้ำกับคนที่มีอยู่ในเครื่องไม่ได้ ทั้งตอนเพิ่มผู้ใช้และตอนแก้ข้อมูลพนักงาน
- กู้คืนไฟล์สำรองของคนอื่นที่มีบัญชีในเครื่องนี้ไม่ได้
- ลืม PIN จะล้างเฉพาะข้อมูลของคนนั้น
- เครื่องที่ใช้ร่วมกัน ควรตั้งล็อกอัตโนมัติ 1–3 นาที และกดล็อกแอปทุกครั้งที่ส่งเครื่องต่อ

## ขั้นการขาย (สถานะโครงการ)

| สถานะ | ความหมาย |
|---|---|
| Lead/Visit | เจอโครงการ / เข้าหน้างานแล้ว ยังไม่ได้คุยกับผู้ตัดสินใจ |
| Contact | ได้คุยกับผู้ติดต่อแล้ว |
| Opportunity | มีความต้องการชัดเจน กำลังเสนอแบบหรือราคา |
| Close Sale | ได้ใบสั่งขาย (SO) |
| ไม่ได้งาน / เลื่อน/ระงับ | ปิดโครงการโดยไม่ได้งาน หรือพักไว้ |

ข้อมูลเดิมจากเวอร์ชันก่อน 1.3.0 ถูกแปลงสถานะให้อัตโนมัติ: ใหม่ → Lead/Visit, นำเสนอแล้ว → Contact, เสนอราคาแล้ว/เจรจา → Opportunity, ได้งาน → Close Sale

## บันทึกย้อนหลัง

- โครงการใหม่และการติดตามเลือก **วันที่ติดต่อจริง** ได้ ระบบเก็บวันที่และเวลาที่บันทึกจริงไว้อัตโนมัติ
- ไฟล์ Excel มีคอลัมน์ `วันที่ติดต่อโครงการ`, `วันที่บันทึกในระบบ` และ `บันทึกย้อนหลัง (วัน)` ใน sheet Projects, FollowUps และ Sales
- บันทึกย้อนหลังเข้าเดือนที่ปิดงวดแล้วไม่ได้ ต้องเปิดงวดใหม่ก่อน

## รอบประจำสัปดาห์

1. ไปที่ **ข้อมูล/สำรอง** ตั้งรหัสผ่านไฟล์สำรอง แล้วกด **สำรองตอนนี้**
2. เก็บไฟล์สำรองไว้ใน OneDrive ของบริษัท
3. ถ้าต้องการไฟล์ Excel ไว้ดูเอง กด **ส่งออก Excel** (ไฟล์ไม่เข้ารหัส เก็บในพื้นที่ของบริษัทฯ เท่านั้น)

## รอบประจำเดือน (ต้นเดือน)

1. หน้าวันนี้จะแสดงแถบ **ยังไม่ได้ปิดงวด [เดือนก่อน]** แตะเพื่อเปิดหน้าของเดือนนั้น
2. ตรวจว่าบันทึกการติดตามและ SO ของเดือนนั้นครบ แล้วกด **ปิดงวด** ระบบจะบันทึกสถานะของทุกโครงการ ณ วันสุดท้ายของเดือน และล็อกการติดตามและ SO ที่ลงวันที่ในเดือนนั้น
3. กด **ส่งออก Excel เดือนนี้** ไฟล์มี sheet `MonthlySnapshot` สำหรับดู Funnel เทียบเดือน
4. ถ้าต้องแก้ข้อมูลเดือนที่ปิดแล้ว กด **เปิดงวดใหม่** แก้ แล้วปิดงวดและส่งออกอีกครั้ง
5. ดูย้อนหลังได้ที่ **ผลงาน → ประวัติรายเดือน · ปิดงวด**

## ล้างข้อมูลเก่าออกจากเครื่อง

- ทำได้เฉพาะเดือนที่ปิดงวดแล้ว เก่ากว่า 2 เดือนขึ้นไป และส่งออก Excel หลังปิดงวดแล้ว
- ระบบล้างเฉพาะโครงการที่จบแล้ว (Close Sale / ไม่ได้งาน / เลื่อน / ลบแล้ว) ที่มีกิจกรรมล่าสุดในเดือนนั้น โครงการที่ยังติดตามอยู่ไม่ถูกล้าง
- ก่อนล้าง ระบบดาวน์โหลดไฟล์เก็บข้อมูลที่เข้ารหัส `PS_archive_[EmpID]_[เดือน].json` เก็บไว้ใน OneDrive ของบริษัท และกู้คืนได้จากหน้าข้อมูล/สำรอง
- ยอดสรุปของเดือนที่ล้างแล้วยังดูได้ในหน้าประวัติรายเดือน

## นำเข้าข้อมูลเดิมจาก Excel

0. กด **ดาวน์โหลดไฟล์ต้นแบบสำหรับกรอกข้อมูลเดิม** ในหน้าข้อมูล/สำรอง ไฟล์มีรายการเลือก (dropdown) และวิธีกรอก

1. ไปที่ **ข้อมูล/สำรอง → นำเข้าข้อมูลเดิมจาก Excel** แล้วเลือกไฟล์ .xlsx หรือ .csv ที่ใช้หัวคอลัมน์แบบเดิมของทีม
2. ระบบหาแถวหัวคอลัมน์ที่มี "ชื่อโครงการ" ให้เอง แถวที่ชื่อโครงการซ้ำกันรวมเป็นโครงการเดียว และแต่ละแถวเป็นการติดตาม 1 ครั้ง
3. ถ้ามีคอลัมน์ Emp ID ระบบนำเข้าเฉพาะแถวของตัวเอง
4. ตรวจผลก่อนกด **นำเข้า** และยกเลิกการนำเข้าทั้งชุดได้ภายหลัง
5. ไฟล์เดิมไม่มีมูลค่า SO ต้องเปิด SO แต่ละรายการแล้วกรอกมูลค่า และผู้ติดต่อจากไฟล์เดิมต้องยืนยันความยินยอมเมื่อติดต่อครั้งถัดไป

## การอัปเดตแอป (ข้อมูลในเครื่องไม่หาย)

ข้อมูลไม่ได้อยู่บน GitHub แต่อยู่ในเครื่องของพนักงานแต่ละคน GitHub เก็บเฉพาะไฟล์โปรแกรม

1. **แจ้งทีมให้สำรองข้อมูลก่อน** วันอัปเดต (ข้อมูล/สำรอง → สำรองตอนนี้)
2. อัปโหลดไฟล์ทั้งชุดจาก zip ทับไฟล์เดิมใน repository เดิม (ชื่อไฟล์เดิมทุกไฟล์) แล้วกด Commit changes
3. รอ GitHub Pages อัปเดต 1–3 นาที
4. พนักงานเปิดแอป จะเห็นการ์ด **มีเวอร์ชันใหม่ของแอป** แตะเพื่อโหลดใหม่ ข้อมูลในเครื่องยังอยู่ครบ
5. อัปเดตจากเวอร์ชันก่อน 1.7: หน้าแรกจะแสดง **เลือกข้อมูลใหม่หลังอัปเดต N โครงการ** ให้เลือกรูปแบบโครงการ สถานะหน้างาน และรายการย่อยที่ยังว่างทีละโครงการ ค่าเดิมทุกช่องเก็บไว้ (ดูได้ในหน้าโครงการ และคอลัมน์ `ค่าเดิมก่อนอัปเดต v1.7` ใน Excel)

ข้อมูลจะ "หายจากสายตา" เฉพาะกรณีลิงก์เปลี่ยน (เปลี่ยนชื่อ repository, บัญชี หรือโดเมน) หรือพนักงานล้างข้อมูลเบราว์เซอร์ ถ้าจำเป็นต้องย้ายลิงก์ ให้ทุกคนสำรองจากลิงก์เดิม แล้วกู้คืนในลิงก์ใหม่

สำหรับผู้พัฒนา: เมื่อแก้ `index.html` ให้เปลี่ยน `APP_VERSION` และเปลี่ยน `CACHE` ใน `sw.js` ให้ตรงกันทุกครั้ง

## ประสิทธิภาพเมื่อข้อมูลสะสม

ทดสอบด้วยข้อมูลจำลอง 1 คน 1 ปี (2,400 โครงการ 16,000 รายการ) บน Chrome คอมพิวเตอร์: ปลดล็อกถึงหน้าแรกประมาณ 4 วินาที ค้นหาไม่เกิน 0.1 วินาที เปิดหน้าโครงการ แผนงาน ผลงาน ไม่เกิน 1 วินาที ส่งออก Excel 4 วินาที (ไฟล์ประมาณ 3 MB) มือถือรุ่นเก่าอาจช้ากว่านี้ 2–3 เท่า เวลาปลดล็อกเพิ่มตามจำนวนรายการ จึงควรใช้ **ล้างข้อมูลเก่าออกจากเครื่อง** ทุกเดือนตามรอบประจำเดือน

## สำรองข้อมูลและรูป

- ไฟล์สำรองมีข้อมูลทั้งหมด และรูปของโครงการที่ยังติดตามอยู่ (กำลังติดตาม และเลื่อน/ระงับ)
- รูปของโครงการที่จบแล้วไม่รวมในไฟล์สำรองโดยอัตโนมัติ เพื่อให้ไฟล์ไม่ใหญ่เกินไป ถ้าต้องการรวม เปิดสวิตช์ **รวมรูปของโครงการที่จบแล้ว** ก่อนกดสำรอง
- ความเสี่ยง: ถ้าเครื่องหายและไม่ได้เปิดสวิตช์นี้ รูปของโครงการที่จบแล้วจะกู้คืนไม่ได้ (ข้อมูลอื่นกู้คืนได้ครบ)

## ความปลอดภัยและ PDPA

- ข้อมูลในมือถือเข้ารหัส AES-256-GCM ด้วยกุญแจที่สร้างจาก PIN (PBKDF2-SHA256 250,000 รอบ) และล็อกอัตโนมัติเมื่อไม่ใช้งาน
- ลืม PIN แล้วกู้ไม่ได้ ต้องล้างข้อมูลแล้วกู้คืนจากไฟล์สำรอง
- ไฟล์ Excel ที่ส่งออก **ไม่เข้ารหัส** เก็บเฉพาะในพื้นที่ของบริษัทฯ · ถ้าจะส่งให้ AI วิเคราะห์ ใช้ปุ่ม **ส่งออกสำหรับวิเคราะห์** (ไฟล์ลงท้าย `_ANALYSIS.xlsx`) และใช้กับ AI ที่บริษัทอนุมัติเท่านั้น
- ข้อความสรุปส่ง Teams ไม่มีชื่อและเบอร์ของผู้ติดต่อ
- Repository เป็น Public ห้ามใส่ข้อมูลจริง รหัสผ่าน หรือ key ใด ๆ ลงในไฟล์

## พร้อมย้ายขึ้น server (ระยะ C)

ทุกรายการมี UUID, Emp ID, `createdAt`, `updatedAt` และสถานะ `synced` ชนิดรายการ (`kind`) มี project, follow, sale, quote และ month (รูปแบบข้อมูลเวอร์ชัน 2) ส่วนจัดเก็บข้อมูลแยกไว้ในออบเจกต์ `Store` ใน `index.html` เมื่อ IT เปิด API ให้แก้เฉพาะส่วนนี้ให้ส่งรายการที่ `synced = false` ขึ้น server หน้าจออื่นไม่ต้องแก้ โครงสร้างคอลัมน์ Excel (Projects, FollowUps, Sales, Quotations, Contacts, MonthlySnapshot) ใช้เป็นต้นแบบตารางฐานข้อมูลได้ทันที


## ข้อจำกัดด้านความปลอดภัยที่ฝ่าย IT ควรทราบ (จากการตรวจ v1.11.1)

- **PIN 6 หลัก** ป้องกันคนที่หยิบมือถือไปเปิดแอปได้ แต่ถ้ามีผู้คัดลอกฐานข้อมูลในเครื่องออกไปพร้อมเวลาและเครื่องที่แรงพอ จะเดา PIN ครบทุกค่าได้ภายในหลายชั่วโมง การล็อกเมื่อใส่ผิดป้องกันได้เฉพาะการเดาผ่านหน้าแอป ทางแก้ระยะยาวคือผูกกุญแจกับอุปกรณ์ (Face ID / Passkey) หรือให้เซิร์ฟเวอร์ถือกุญแจในระยะ C
- **โดเมน GitHub Pages** เว็บทุก repository ใต้ `[account].github.io` ใช้ origin เดียวกัน จึงเข้าถึงฐานข้อมูลในเครื่องของแอปนี้ได้ ควรใช้บัญชีหรือ organization แยกสำหรับแอปนี้เท่านั้น หรือใช้โดเมนของบริษัท
- **ข้อมูลที่ไม่เข้ารหัสในเครื่อง** รายชื่อผู้ใช้ในเครื่อง (Emp ID และชื่อเล่น) และจำนวนรายการแต่ละประเภท
- **ไฟล์ที่ส่งออก** Excel ฉบับเต็มไม่เข้ารหัส ไฟล์สำรองเข้ารหัสด้วยรหัสผ่าน ควรเก็บในพื้นที่ของบริษัทเท่านั้น
- **ฟอนต์** โหลดจาก Google Fonts ทำให้ IP ของผู้ใช้ส่งไปที่ Google
